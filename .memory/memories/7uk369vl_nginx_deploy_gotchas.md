Opfield nginx defaults that surprise application deployers (verified in code on 2026-10-01):

- Proxy hosts and additional routes store `websocketSupport` with default `false` (`proxy_hosts.websocket_support`, `proxy_additional_routes.websocket_support`). Without it the generated config sets `proxy_set_header Connection "";` and sends no `Upgrade` header, so WebSocket upgrades fail. With it the generator/template adds `Upgrade $http_upgrade` and `Connection "upgrade"` (`services/nginx-config-generator.service.ts`, `modules/proxy/nginx-template.service.ts`). A blue/green deployment upstream (secure link plus the deployment router) and Cloudflare then pass the upgrade end to end.
- Blue/green deployment routers (`gwdep-<id>-router`, nginx:alpine, config generated by `packages/daemons/docker/internal/docker/deployment_router.go`) set `client_max_body_size 0;` and `proxy_request_buffering off;` since 2026-09-27. Before that, nginx's 1 MB default returned an HTML 413 for larger uploads even when the ingress route allowed more.
- An existing router picks up a changed router template only on its next rollout; redeploying the same image regenerates it.
- To find which layer limits a request body, send a large unauthenticated PUT: the app's own JSON 401 means the request passed every proxy, while an HTML 413 means a proxy stopped it.
